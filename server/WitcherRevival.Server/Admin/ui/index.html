Sterowanie warunkami
Komunikaty: format i publikacja
  1. Wybierz język treści, np. PL. Język panelu jest niezależny. Zmiana języka treści wymaga odrzucenia niezapisanej wersji.
  2. Dodaj wpis. Wymagane są tytuł, treść i prawidłowa data. Krótki opis oraz okładka mogą być puste. Same spacje w tytule lub treści są błędem.
  3. Data jest wyświetlana w grze. Przyszła data nie opóźnia publikacji. W formularzu wybierz datę z kalendarza; JSON używa DD/MM/RRRR.
  4. Własną okładkę prześlij najpierw przez bibliotekę, a potem wybierz jej nazwę we wpisie. Wysłanie obrazu nie publikuje komunikatu. Pusta okładka wybiera obraz domyślny.
  5. Sprawdź podgląd tekstu, język, liczbę wpisów i usunięcia. Publikujesz całą listę danego języka. Usunięcie ostatniego wpisu wymaga publikacji pustej listy.
  6. Po zapisie sprawdź potwierdzenie i odczyt z serwera. Gracz pobiera treść przy kolejnym otwarciu „Co nowego”; restart silnika nie jest potrzebny.

Lista zawiera najwyżej 100 wpisów. ID jest dodatnią liczbą całkowitą, unikalną w tej liście. Grupa zawiera 1–128 znaków bez średnika. Formularz generuje oba identyfikatory. Wyróżnić można jeden istniejący wpis; featured: 0 oznacza brak wyróżnienia.

Nazwa okładki: 1–64 litery A–Z, cyfry, _ lub -, następnie .png, .jpg lub .jpeg. Bez spacji, polskich liter i katalogów. Plik do 2 MiB, maksymalnie 4096 × 4096 px. Pełny adres HTTP(S) jest dopuszczony, lecz jego dostępność zależy od zewnętrznego serwera.

Błąd wskazuje numer wpisu i pole. Kliknij go, popraw wartość i opublikuj ponownie. Niepoprawny wpis blokuje zapis całej listy. Konflikt rewizji wymaga porównania aktualnego zapisu; nie usuwa wersji roboczej.

Przykład dokumentu wiadomości. Edytor sam dołącza aktualną rewizję do żądania zapisu. Nazwy pól i typy są obowiązkowe; treść traktuj jako zwykły tekst, a wygląd sprawdź w grze.

{
  "featured": 1,
  "news_list": [{
    "id": 1,
    "group_id": "news-1",
    "title": "Update",
    "short_description": "Test update",
    "date": "04/10/2026",
    "image_url": "",
    "content": "The test world is available."
  }]
}

Brak tłumaczenia w grze uruchamia kolejno język bazowy i domyślny język serwera. Pusta, poprawna lista jest osobną publikacją; nie oznacza brakującego pliku.

Redaguj komunikaty
Zadania i wydarzenia

W rotacji dziennej ustaw wagi i wymagane poziomy; zmiany dotyczą kolejnych losowań. Zasada stempli działa przy następnym sprawdzeniu serii. Nowy katalog definicji jest przygotowywany do osobnego zastosowania w oknie serwisowym, a nie od razu uruchamiany.

Zadania i wydarzenia
Gracze: postęp, bibeloty i kilometry
  1. Otwórz Gracze, znajdź profil i wybierz Szczegóły. Sprawdź ID, nazwę oraz etykietę przed interpretacją danych.
  2. Rozwiń fabułę, zadania dzienne, czasowe, bibeloty lub stemple. Tabele pokazują licznik, cel i stan nagrody. Wpisy można wyszukać po warunku, nazwie lub ID.
  3. Odśwież postęp gracza, aby ponownie odczytać zapis. Odczyt nie losuje zadań, nie przyznaje bibelotów i nie odbiera nagród. Liczniki okien czasowych mogą wymagać aktualizacji przez grę.

Zadanie gotowe do odbioru nie oznacza nagrody odebranej. Odebrane zadania dzienne znikają z zapisu; nie ma pełnej historii ich ukończenia. Końcowa nagroda wydarzenia wymaga odbioru nagród poszczególnych zadań. Bibeloty są przyznawane automatycznie po sprawdzeniu warunku w grze.

Dystans to kilometry naliczone w grze. Historyczny stan mógł uwzględniać teleporty. Zaakceptowane odcinki ochrony są pokazane osobno, od jej uruchomienia lub ostatniego resetu, kopii albo przywrócenia. Brak danych nie oznacza zera ani potwierdzonej pieszej trasy.

Etykieta zmienia opis w panelu. Kopiowanie, reset, przywrócenie i zegar fabuły wymagają zamknięcia LAB oraz sprawdzenia profilu docelowego. Kopia zastępuje postęp celu; nie przenosi przypisań urządzeń. Po zmianie zapisu uruchom LAB ponownie.

Gracze
Wersje robocze, konflikt i odzyskiwanie

Przejście między sekcjami zachowuje niezapisane formularze w tej karcie. Zamknięcie lub przeładowanie strony może je utracić. Odświeżenie danych wymaga zgody na odrzucenie zmian w bieżącym widoku.

Konflikt oznacza, że ktoś zmienił zapis od czasu odczytu. Porównaj aktualną wersję przed ponownym zapisem. Po błędzie sieci sprawdź historię operacji: żądanie mogło już zostać wykonane.

Historia zawiera wynik i identyfikator operacji. Dostępne kopie można przejrzeć przed przywróceniem; przywrócenie ustawień zapisuje kolejną wersję. Nigdy nie traktuj samego kliknięcia jako potwierdzenia zmiany.

Historia operacji
Testerzy: kod, dostęp i profil

Hasło i CAPTCHA chronią pobieranie APK. Zatwierdzenie kodu instalacji jest osobną kontrolą dostępu do gry; pobranie pliku nie zatwierdza urządzenia.

Otwórz rejestrację, poproś testera o uruchomienie LAB, odszukaj jego kod i zatwierdź nowy osobny profil lub świadomie wybierz istniejący zapis.

Czas dostępu liczony jest od chwili zapisu. Ustawienie krótszego okresu może skrócić istniejący dostęp. Zmiana przypisania rozłącza instalację i zachowuje oba zapisy; nie kopiuje postępu. Inne instalacje tego profilu zachowują przypisanie.

Po błędzie sprawdź historię i odśwież stan przed kolejną zmianą. Zatwierdzenie instalacji nie potwierdza jeszcze wejścia testera do gry.

Testerzy
Silnik: start, stop i restart
  1. Otwórz Silnik i sprawdź świeżość odczytu, host, wersję oraz aktywne sesje. Proces działający bez gotowości jest pokazany oddzielnie.
  2. Wybierz działanie i sprawdź jego zakres w potwierdzeniu. Stop oraz restart przerywają połączenia graczy. Start korzysta z aktualnie wybranej wersji; nie wdraża nowego pakietu.
  3. Po zatwierdzeniu obserwuj operację aż do wyniku. Gotowość może wymagać do 3 minut, w tym oczekiwania na zwolnienie portów.
  4. Po utracie odpowiedzi wybierz Sprawdź wynik. Panel szuka tego samego identyfikatora operacji i nie wysyła ponownie polecenia. Odśwież stan przed nową decyzją.

Panel i jego historia operacji silnika działają w oddzielnej usłudze. Zatrzymanie gry pozostawia możliwość jej uruchomienia. Pozostałe zakładki wymagające API gry zgłaszają niedostępność. Mapy, brama HTTPS i pobieranie APK są osobnymi usługami; przyciski silnika ich nie restartują.

Silnik
Skąd pochodzą mapy

Podkład powstaje z lokalnie przygotowanych danych OpenStreetMap. Adapter tworzy kafle zgodne z formatem klienta. Osobna usługa rozmieszczenia wybiera miejsca spotkań z tego samego indeksu. Projekt nie wymaga klucza Google Maps ani pobierania obrazów z publicznego serwera kafli OSM.

Pokrycie zależy od zaimportowanego obszaru. Poza nim nie ma gwarancji podkładu ani prawidłowych miejsc spotkań. Zmiana wag potworów nie rozszerza pokrycia. Import i indeksowanie nowego obszaru wymagają narzędzi serwerowych opisanych w dokumentacji repozytorium.
