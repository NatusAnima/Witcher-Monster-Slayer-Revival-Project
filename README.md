# Witcher: Monster Slayer — Revival Project

## Overview
This project aims to resurrect the discontinued augmented reality game **The Witcher: Monster Slayer** (`com.spokko.witchermonsterslayer`, servers shut down June 2023). 

Since the original backend is dead, the project involves reverse-engineering the Unity IL2CPP client (arm64 v1.0.43) to understand its proprietary TCP protocol, bypassing certain client-side modules via runtime memory patching (Frida), and building a custom ASP.NET Core game server to hydrate the game state and drive gameplay.

## Architecture
- **Client Modding:** The original APK runs on a physical Android device. A Frida gadget is injected into it. We use an ADB tunnel and a Frida script (`hook.js`) to intercept libc `connect()` calls (redirecting the dead prod IP to localhost), bypass unhandled IL2CPP modules, and log diagnostics.
- **Backend Server:** A custom C# ASP.NET Core application (`server/WitcherRevival.Server`) that listens on raw TCP port `4253` for game traffic and port `8080` for HTTP static data (the host port is configurable with `Http__Port`; the phone always uses 8080 through `adb reverse`). It implements the custom big-endian framed wire protocol expected by the client.

## Setup From a Fresh Clone
You provide the game files: the **v1.0.43 (build 200098) arm64-v8a APK** (its `lib/arm64-v8a/libil2cpp.so` must have SHA-256 `935940bd88708ea786a8aea961fc780082db95fd4921f683f775238d433d0846`, since every RVA in `hook.js` depends on that build) and its OBB `main.200098.com.spokko.witchermonsterslayer.obb`.

Prerequisites: an arm64 Android phone with USB debugging (emulators can't run the arm64-only client under Frida), the .NET 10 SDK, Python 3.10+, JDK 21 on `PATH`, and Android platform-tools unzipped into `tools/platform-tools/`.

1. `pip install -r tools/requirements.txt`
2. Build the patched client: `python tools/patch/patch_apk.py "<original.apk>" witcher_gadget.apk` (adds Frida Gadget 17.15.3 and re-signs with a debug key; first run downloads the gadget and `uber-apk-signer` into `tools/patch/.cache/`).
3. Install it: `tools/platform-tools/adb install witcher_gadget.apk` (uninstall any differently-signed copy first), then `tools/platform-tools/adb push main.200098.com.spokko.witchermonsterslayer.obb /sdcard/Android/obb/com.spokko.witchermonsterslayer/`.
4. Play: `python tools/restart.py` builds and starts the server, sets up the adb tunnels, launches the game and keeps the Frida hooks attached. Leave it running and rerun it to restart everything; logs go to `scratch/`.

Quest steps spawn at fixed coordinates (`TutLat`/`TutLng` in `GameSocketService.cs`); edit them or fake your GPS location. Player state lives in `server/WitcherRevival.Server/data/` (gitignored).

The reverse-engineering tools need more local, gitignored files: the APK unzipped into `tools/apk_extracted/` (and OBB bundles in `tools/apk_extracted/bundles/`), Il2CppDumper output in `tools/dump/`, and Ghidra 12.1.4 in `tools/ghidra-dist/`. See the toolchain notes in `HANDOFF.md`.

## Repository Structure
- `server/WitcherRevival.Server/`: The custom backend server. Key files include `GameSocketService.cs` (TCP session and RPC dispatch) and `PreloaderStaticData.cs` (static game data container).
- `tools/patch/`: Contains `hook.js` (the active Frida hook), `frida_run.py` (the Python script to inject the hook into the running game) and `patch_apk.py` (builds the Gadget-patched client from your APK).
- `tools/restart.py`: One-command restart of the server and the game, with Frida attached.
- `tools/ghidra_decomp.py`, `tools/il2cpp_callers.py`, `tools/unity_extract/`: Reverse-engineering helpers (decompile methods by RVA, find call sites, read story/quest data out of the OBB bundles).
- `tools/platform-tools/`: Contains `adb.exe`, necessary for port forwarding and launching the app on the phone.
- `tools/dump/`: Contains heavy reverse-engineering data (`dump.cs`, `catalog.json`) generated by Il2CppDumper. These are ignored by Git but are critical for searching RVAs, undocumented API payloads, and Addressable asset slugs.
- `docs/`: Technical reference documentation for the protocol, API payloads, and memory maps.
- `HANDOFF.md`: The active session tracker. **Start here when resuming development.**
